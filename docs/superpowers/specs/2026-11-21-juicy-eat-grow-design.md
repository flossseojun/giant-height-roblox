# 먹는 순간 · 커지는 순간 손맛 + 진짜 음식 모양 — 짧은 설계

날짜: 2026-11-21 · 상태: 승인됨("승인")

## 왜
키 키우기가 밋밋했다: 음식이 색깔 공이고, 먹으면 그냥 사라지며, 몸이 툭 커진다. 핵심 반복(줍기 → 커지기)의 손맛을 높인다.

## 정한 것 (사용자 승인)
- **음식 모양**: 12종 + 황금 우유 + 우유 비를 파트 여러 개로 진짜 모양(우유팩, 계란빵, 호떡, 옥수수, 연잎 핫도그, 한우 접시, 비빔밥 그릇, 은행, 약수 병, 별빛 우유, 별사탕, 별똥별 조각). 천천히 돌며 둥실.
- **먹는 순간**: 음식이 입으로 빨려 들어옴(날아오며 작아짐), 음식 색 부스러기, "냠" 소리, 머리 위 "+3cm 호떡". **콤보**: 2초 안 연속이면 "콤보 ×N", 소리 높아짐.
- **커지는 순간**: 0.3초 부드럽게 커짐, 발밑 반짝이, 카메라 살짝 물러남. **키 돌파**: 원형 충격파, 화면 번쩍, 팡파레, 비교 문구(30cm 고양이, 1m 강아지, 2m 문, 6m 2층집, 12m 상가, 45m 아파트, 114m 오스타 코아루, 그 위로 남산타워·용문산·구름 …).
- 방식: 서버는 판정·부드러운 크기만, 연출은 각자 화면. 작은 크기 변화는 바로 반영.

## 방식 (하나뿐)
- 서버 음식 파트는 투명 히트박스(속성 `FoodId`, `Golden`), 클라이언트 `FoodVisuals`가 그 위에 모양을 그리고 돌림 → 서버 가벼움.
- 서버가 먹은 사람에게 `Ate(foodId, 위치)` → 클라이언트 연출. 이름은 `Gained`의 source(음식 id)로 찾음.
- 부드러운 크기: `HeightService.applyBody`가 크기 차이가 5% 이상이면 5단계로 나눠 0.3초 동안 `ScaleTo`(새 변화가 오면 이전 단계 취소), 아니면 바로.
- 돌파 판정·콤보 계산은 순수 Logic(테스트).

## 실패로 치는 것
- 음식 수십 개 + 거인 여럿에서 렉, 먹었는데 모양이 남아 있음, 접속 직후(저장 불러올 때) 돌파 연출이 줄줄이 뜸.
